## 추천안 B: 스튜디오

밝은 종이색 바탕, 짙은 본문, 사람별 절제된 포인트 색, 큰 제목과 타이포그래피.
작은 기능 타일을 먼저 나열하기보다 지금 중요한 관심사와 선택 가능한 다음 행동을 먼저 보여준다.
모바일은 하단 탐색, PC는 왼쪽 탐색과 넓은 본문. 특정 기기 폭에 화면을 고정하지 않는다.

| 구성원 | 홈의 중심 | 기존 내용 연결 |
|---|---|---|
| 하음 | 웹툰 작업실 | 학교 → 전형·실기 → 포트폴리오·일정·데뷔 |
| 하울 | 대학 탐색 공간 | 대학 → 학과·지원자격 → 일정·확인, 문제은행 |
| 하람 | 작은 주방 | 메뉴 → 레시피 → 준비물·만드는 단계, 저장 |
| 엄마·아빠 | 가족의 오늘 | 전체 기능, 화면 노출 설정, 학습·생활 |

비교안 A 정돈형은 대표 영역을 작게 하고 목록 접근을 빠르게 한다.
비교안 C 매거진형은 타이포 표지를 크게 펼치고 콘텐츠를 세로 목록으로 보여준다.
세 안은 콘텐츠는 같고 정보 밀도·영역 배치가 다르다.

## 유지 범위

- 앱의 `features.js`, `career.js`, `webtoon.js`, `recipes.js`를 빌드 시 읽어 HTML에 삽입한다.
- 기존 19개 기능의 이름·그룹·아이별 기본 노출을 유지한다. 교회는 아빠 전용 유지.
- 본문 데이터와 실서비스의 점수·기록·인증·DB·AI 함수를 수정하지 않는다.
- 데이터가 없는 실제 성적·완료율·D-day를 만들지 않는다.
- 입시 조건의 정확성을 이번 디자인 작업에서 새로 검증한 것은 아니다. 기존 확인 안내도 유지한다.
- 홈의 환영 문구와 섹션 제목은 디자인용 새 문안이다. 기존 교육 본문과 구분한다.
- 개인별 대표 화면을 별도 자동 이동 대신 개인화된 홈에서 곧바로 여는 구성을 제안한다.
  실제 적용 때 현재 `LANDING` 자동 이동과 중복되지 않도록 정리해야 한다.

## 클릭 가능한 범위

가족 전환 / 3가지 레이아웃 / 그룹과 전체 기능 검색 / 대학·웹툰 학교 상세 /
입시 자료 탭 / 레시피 분류·저장·재료·단계 체크 / 부모의 자녀 노출 스위치.

입시박사와 기존 학습·생활 기능은 연결 위치를 설명하는 창만 연다. 실제 AI 호출과 DB 저장은 없다.
노출 스위치와 레시피 즐겨찾기는 시안 메모리에만 적용하며 새로고침하면 초기화된다.
실제 서비스에서 아이들의 비공개 마음 기록을 부모에게 자동 공개하는 변경은 제안하지 않는다.

## 실제 적용 전에 보완할 내용

1. 하람 요리 카드에 실제 완성 사진을 넣으면 메뉴 선택이 훨씬 쉬워진다. 현재 저장소에 해당 사진이 없어 시안은 제목·시간·소개로 구성했다. 사진 촬영/선정은 별도 작업이다.
2. 입시 대학·학과·전형 데이터는 현행 모집요강과 대조하는 별도 검증이 필요하다. 디자인 변경으로 지원자격이 확인되는 것은 아니다.
3. 기존 요거트 아이스크림 컵 소개는 ‘칼도 안 쓰는’이라고 하지만 단계에는 과일을 자르라는 내용이 있다. 본문은 보존했다. 실제 적용 전에 손질된 과일 사용 또는 어른 도움 안내로 일치시킬 것을 제안한다.
4. 요리·문제풀이 기기 간 동기화는 기존 localStorage 구조의 별도 개선 사항이다. 이번 UI 시안에서 서버 저장을 새로 만들지 않았다.
5. Pretendard 우선으로 지정하되 없는 PC에서는 시스템 글꼴로 표시한다. 실제 적용 시 기존 폰트 로딩 정책을 통일한다.
