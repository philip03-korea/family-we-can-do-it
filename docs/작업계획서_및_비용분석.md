# FamTalk — 작업 계획서 & 비용 분석

> 작성일: 2026-06-09
> 목적: TTS/STT/LLM API 과금 구조를 이해하고, **비용을 최소화하는 아키텍처**로 개발 순서를 확정한다.

---

## 1. 핵심 질문 — "누를 때마다 TTS 생성하면 계속 과금되는 거 아니야?"

**맞습니다. 그래서 그렇게 만들면 안 됩니다.**

영어 학습 콘텐츠는 두 종류로 나뉩니다.

| 종류 | 예시 | 특성 | TTS 전략 |
|------|------|------|----------|
| **고정 콘텐츠** | 단어, 예문, 커리큘럼 문장, 주간 토론 지문 | 5명이 공유, 평생 동일, 유한함 | **한 번 생성 → 저장 → 영구 재사용** |
| **동적 콘텐츠** | LLM 실시간 회화 답변, 즉석 교정 문장 | 매번 다름, 사용자별 | **생성 시 캐싱(텍스트 해시 키)** → 같은 문장 재요청은 0원 |

> **결론: "누를 때마다 API 호출"이 아니라, "처음 한 번만 생성하고 음성 파일로 저장한 뒤 그 파일을 재생"한다.**
> 두 번째 누름부터는 API 비용이 **0원**이다.

## 2. TTS 캐싱 아키텍처

```
[학습 화면에서 🔊 버튼 누름]
        │
        ▼
  audio_cache 테이블 조회  ── (text_hash = SHA256(text + voice + lang))
        │
   ┌────┴─────┐
 있음        없음
   │          │
   ▼          ▼
저장된     TTS API 1회 호출
파일 재생   → 오디오 파일 저장(스토리지)
(0원)      → DB에 경로 기록
            → 재생
            (이후부터는 0원)
```

### 저장 위치
- **개발/소규모:** 서버 로컬 디스크 `/storage/tts/{hash}.mp3` + 정적 서빙
- **운영/확장:** 오브젝트 스토리지(S3 / Cloudflare R2 — R2는 egress 무료라 음성 서빙에 유리)

### DB 스키마 (캐시 테이블)
```sql
CREATE TABLE audio_cache (
  text_hash   VARCHAR(64) PRIMARY KEY,   -- SHA256(text + voice + lang + speed)
  text        TEXT NOT NULL,
  voice       VARCHAR(32) NOT NULL,
  lang        VARCHAR(8)  NOT NULL,
  file_path   TEXT NOT NULL,
  char_count  INT NOT NULL,
  created_at  TIMESTAMPTZ DEFAULT now(),
  hit_count   INT DEFAULT 0              -- 재사용 횟수(비용 절감 추적용)
);
```

### 사전 생성(Pre-generation) 배치
커리큘럼 단어·예문은 사용자가 누르기 **전에** 배치로 미리 다 만들어 둔다.
- A~F 6레벨 전체 단어/예문을 야간 배치 1회 실행 → 전부 캐시 적재
- 이후 학습 중 발생하는 TTS 호출은 사실상 **동적 회화뿐**

## 3. 비용 분석 (5인 가족 기준)

### 3-1. 단가 (2026년 기준, USD)

| 서비스 | 용도 | 단가 |
|--------|------|------|
| TTS (OpenAI tts-1 / Azure Neural급) | 듣기·발음 음성 | **~$15 / 100만 자** |
| TTS (Google Standard) | 저가 대안 | ~$4 / 100만 자 |
| STT (Whisper API) | 발음 녹음 → 텍스트 | **$0.006 / 분** |
| 발음 평가 (Azure Pronunciation Assessment) | 억양·정확도 점수 | ~$1 / 오디오 1시간 |
| LLM 회화 (Haiku급 경량 모델) | 회화·교정 | ~$1 입력 / $5 출력 (100만 토큰당) |

> ⚠️ 단가는 변동되므로 실제 발주 전 각 콘솔에서 재확인 필요.

### 3-2. ❌ 캐싱 없이 (누를 때마다 생성) — 나쁜 설계

| 항목 | 계산 | 월 비용 |
|------|------|---------|
| 고정 콘텐츠 TTS | 1인 100문장/일 × 3회 재생 × 50자 = 15,000자/일 × 5인 × 30일 = **225만 자** | **~$34/월** |

- 복습을 많이 할수록 **무한 증가** (재생할 때마다 과금)
- 5명이 열심히 쓰면 월 **$100 이상**도 가능
- **이미 만든 똑같은 음성을 매번 돈 주고 다시 만드는 낭비**

### 3-3. ✅ 캐싱 적용 — 권장 설계

| 항목 | 계산 | 비용 |
|------|------|------|
| **고정 콘텐츠 TTS (전체 커리큘럼)** | A~F 전 단어·예문 ~3,000개 × 50자 = 15만 자 | **~$2.3 (1회성, 영구)** |
| 동적 회화 TTS | 1인 30줄/일 × 80자 × 5인 × 30일 = 36만 자 (게다가 흔한 문장은 캐시 적중) | ~$5.4/월 |
| STT (발음 녹음) | 1인 4분/일 × 5인 × 30일 = 600분 | ~$3.6/월 |
| LLM 회화·교정 | 5인 × 30턴/일 × 30일 = 4,500턴 (턴당 ~1k입력/0.5k출력) | ~$16/월 |
| 발음 평가(선택) | 600분 = 10시간 | ~$10/월 (Whisper 자체 점수로 대체 시 $0) |

> **월 합계: 약 $25 ~ $40 (≈ 3.5만 ~ 5.5만 원)**
> 고정 콘텐츠 TTS는 **최초 1회 $2~3로 끝**. 이후 가족 전원이 평생 무료로 재생.

### 3-4. 비교 요약

| | 고정 콘텐츠 TTS | 사용량 증가 시 | 월 총비용(추정) |
|---|---|---|---|
| ❌ 캐싱 없음 | 매 재생마다 과금 | 선형 증가, 상한 없음 | $34~$100+ |
| ✅ 캐싱 적용 | 1회 ~$2.3로 끝 | 거의 불변 | **$25~$40** |

## 4. 비용 절감 추가 전략

1. **사전 생성 배치** — 커리큘럼 음성은 사용자 클릭 전에 전부 미리 생성(클릭 시 API 호출 0).
2. **동적 회화도 해시 캐싱** — "Nice to meet you" 같은 흔한 문장은 한 번만 생성.
3. **모델 계층화** — 회화/교정은 경량 모델(Haiku급), 정밀 채점 등 꼭 필요할 때만 상위 모델.
4. **STT 자체 점수 활용** — Whisper 결과로 1차 발음 비교 → 유료 발음평가 API는 선택 기능으로.
5. **월 사용량 상한(쿼터)** — 사용자/가족 단위 일·월 한도를 두어 폭주 방지.
6. **R2/egress 무료 스토리지** — 음성 파일 다운로드 트래픽 비용 절감.
7. **클라이언트 캐싱** — 한 번 받은 음성은 브라우저(IndexedDB/PWA Cache)에도 저장 → 같은 기기 재방문 시 네트워크/서버 비용도 0.

## 5. 작업 계획서 (개발 순서 — 비용 반영 버전)

기존 CLAUDE.md 7단계를 유지하되, **캐싱/비용 관리를 STEP 2~4에 명시적으로 삽입**한다.

### STEP 1 — 셋업 + 인증
- React + PWA + Tailwind 프론트 / 백엔드(FastAPI 또는 Express) / PostgreSQL / Docker
- 가족 5인 계정·로그인, 역할(부모/자녀) 구분

### STEP 2 — DB 스키마 + 레벨 시스템 + 단어 SRS
- 레벨(A~F), 단어/예문 콘텐츠 테이블
- **`audio_cache` 테이블 포함** ← 비용 핵심
- FSRS 기반 단어 복습 스케줄

### STEP 3 — 학습 UI + **TTS 캐싱 레이어**
- 단어 → 말하기 → 발음/억양 학습 흐름
- 🔊 버튼 = "캐시 조회 → 없으면 1회 생성 후 저장" 로직
- **커리큘럼 음성 사전 생성 배치 스크립트**
- 클라이언트 측 오디오 캐싱(PWA)

### STEP 4 — AI 연동 + **비용 관리**
- LLM 회화·교정 (경량 모델 우선)
- 동적 TTS 해시 캐싱
- **사용량 로깅 + 월 비용 대시보드 + 쿼터**

### STEP 5 — 가족 소통
- WebSocket 채팅, 주간 공통 주제, 가족 대시보드

### STEP 6 — 하울 TOEFL 트랙
- 영역별 훈련, 모의고사 체험, AI 채점

### STEP 7 — 게임화 + 배포 + 운영
- 포인트/배지, 배포, 모니터링
